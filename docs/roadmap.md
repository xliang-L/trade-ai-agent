# 分期实施与验收

## V1 第一阶段闭环

| 里程碑 | 内容 | 验收证据 |
|---|---|---|
| M0 架构与 runtime 验证 | 本架构基线、模拟渠道、Codex/备用 runtime 验证 | harness 准入报告与选型 ADR |
| M1 数据与团队工作台 | 身份权限、CRM、SKU、供应商、内部库存、外部货源、表格导入 | 两业务员隔离与共享库存；导入预览、行错误与重复处理 |
| M2 需求与核验 | SOP 字段收集、历史需求池、结构化匹配、到货任务、核验工作台 | 无货需求可找回；每个候选有来源与版本；只有授权人员可核验 |
| M3 报价与接管 | 金额计算、利润底线、有效期、基础审批、草稿审核、人工接管 | 过期/改价拦截；金额一致；接管并发发送被拦截 |
| M4 WhatsApp 与运行保障 | 实际渠道适配器、Webhook、Outbox、幂等、回执、运行监控、备份 | 真实测试号端到端演练；重启恢复；发送超时处理与恢复演练 |

先验证一条垂直流程，再扩大工作台。M0 不需要完整 UI；M4 受实际账号、权限和供应商能力影响。在数据和渠道未知前不给确定工期。

第一版场景测试至少包括：两个供应商同款不覆盖；地区版本不同不误报；内部库存已锁定不作为可售数；外部未核验不发送正式报价；48 小时未到但货源先过期仍拦截；核验后改价使旧草稿无效；低于底线待主管处理；新到货召回历史询单；重复 Webhook 不重复入池；人工接管时在途回复不发送；业务员不能读未授权客户或成本字段。

## V2 第二阶段

客户分层和 1–3 天触达计划、统一频率限制、社媒图文生成与审核发布、Facebook/Instagram 线索引流、配置化报价审批、KPI 看板。先验证实际平台权限，再承诺平台自动发布。

验收包括：库存事件和计划任务不会对同一客户重复触达；素材生成与发布审批分开；任务过期不能发旧货源；渠道失败可重试和回执追踪；KPI 有明确定义与事件来源。

## V3 第三阶段

多渠道会话和客户身份合并、ERP/销售单/仓库同步、内容排期、供应商评分、采购预测。先定义数据权威来源和冲突处理，再增加预测。

验收包括：同步重复与乱序事件不会覆盖更新数据；身份合并可审计；ERP 库存同步可对账；评分有可解释事实来源；预测结果不能直接承诺库存或成交。

## 开发前待确认

- 当前 Excel/ERP/CRM 数据样例、SKU 命名、库存和销售单的权威来源。
- WhatsApp 使用官方 API、第三方服务商或人工辅助；现有企业账号和测试号。
- 客户归属和跨业务员可见范围；采购、销售、主管分别能看哪些成本字段。
- 币种、报价是否包含运费与税、规则优先级、最低利润和让价权限。
- 核验有效时间、责任人和待办响应时限；哪些标准回复可以自动发。
- 主要语言、部署环境、备份和客户数据留存要求。

这些不阻碍架构设计，但在实现相关模块和真实上线前需确定。

# 需求书 V1.2 与演示对照

本次直接对照《外贸AI Agent需求规格说明书》第一阶段和验收标准修订离线演示。演示使用虚构数据与预设英文对话，不等于生产验收通过。第二、三阶段继续通过原有模块和适配器扩展。

| 需求依据 | 原演示差异 | 本次处理 |
|---|---|---|
| 第九章 48 小时有效报价 | 固定 6 小时演示配置，没有充分解释 | 默认报价和核验 48 小时；不得超过供应源截止；较短货源自动缩短；过期拦截保留 |
| 第十二章 询价 SOP | 初始客户未说版本、颜色，演示直接填写 | Omar 先补齐颜色、区域版本、预算范围、货代和期望时间，再允许匹配核验 |
| 第七章 历史需求 | 到货后直接核验，没有确认需求是否仍有效 | Daniel 到货召回后先展示客户确认，再允许采购核验 |
| 第八章 可解释匹配 | 候选有价格，缺少具体匹配依据 | 展示型号、版本、容量、颜色、数量、有效期及规则置信等级；等级不是模型概率 |
| 第九、十四章 有限谈价与主管审批 | 仅转销售，没有审批动作 | 展示 AI 额度、让价条件、原价留痕；继续压价需主管批准或拒绝并填写原因；不突破底价 |
| 第十三章 知识库与 SOP | 页面没有规则依据 | 增加 SOP 与规则页面，展示询价、核验、报价、谈价和接管原则；尚无真实检索服务 |
| 第十九章 最终结果回写 | 演示停在接管 | 增加人工模拟成交/未成交，回写客户记录和审计；待审批的特殊报价不得直接记录成交 |
| 第十七章 阶段划分 | 容易混淆演示与正式能力 | 增加需求对照页面，明确可演示、真实服务待接入、第二阶段和第三阶段 |

需求书中的成本加 USD 1/2、让价 USD 0.5 是示例，不是硬编码要求。当前成本 + USD 4 的内部底价、最低利润 USD 2、AI 每台让价 USD 1 和目标价优先策略都是明确标注的演示配置，需要业务方确认。不能把客户目标价理解成已承诺购买价格。

## 尚未满足正式验收的部分

- WhatsApp 与 ChatGPT API、真实知识库检索尚未接入；对话为固定场景，不支持任意文本智能理解。
- 库存录入目前是预置到货场景，缺少通用录入、每日批量更新、Excel 导入及供应商资料维护。
- CRM 以预置档案和结果回写演示为主，客户录入、导入、标签修改与完整联系人字段未完成。
- 当前是内部团队演示视角，不提供正式登录、成本权限和角色隔离。客户端报价单隐藏成本不等于完成角色鉴权。
- 主管审批身份为模拟，尚未接入真实账户、审批通知和权限校验。
- 未成交需求已保留，后续订单系统、真实付款、锁货与仓库出货仍未接入。
- 1–3 天触达、社媒图文与发布、KPI 属于第二阶段；多渠道、ERP 和预测属于第三阶段。尚未启用，不展示虚构提升百分比。

## 给老板的五分钟演示

1. 工作概览：说明团队不用靠个人记忆追踪询单、货源和责任人。
2. Omar 完整流程：补齐关键字段 → 比较多供应商 → 采购核验 → 48 小时报价 285 美元。
3. 谈价：285 → 284，整批节省 200 美元；继续要求 283 → 主管审批，原因留痕。展示 AI 有空间，也有边界。
4. 人工结果：购买意向接管或完成审批 → 模拟成交回写 CRM → 操作记录。报价不等于订单，不自动锁货、收款。
5. Daniel 到货召回：无货需求保留 → 新货源匹配 → 先问客户是否仍需要 → 核验报价。说明数据库能把遗忘需求重新变成机会。
6. 展示过期报价拦截及 SOP 与规则，最后用需求对照说明真实接入与后续阶段。

重新展示前：刷新离线文件，进入演示说明并重置模拟数据。旧进度保持旧报价和核验时限，不自动改写历史记录。

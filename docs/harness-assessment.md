# Codex harness 复用评估

结论：可以复用，建议将 Codex app-server 包装成可替换的 AgentRuntime，复用运行循环、会话、流式事件、工具接入和中断；由本项目掌握交易规则与团队数据。当前属于文档级可行性判断，尚未安装或压测 Codex，也未接入真实模型。

## 可复用范围

| 能力 | 建议 |
|---|---|
| 模型与工具循环、长任务上下文 | 通过运行时接口复用 |
| thread/turn 生命周期、事件与中断 | app-server 转换成项目统一事件 |
| 企业工具 | 优先 MCP 连接受控业务网关 |
| SOP 与场景指令 | 用已发布版本构造上下文；权限由网关执行 |
| 运行审批能力 | 可呈现运行时审批；独立于库存核验与报价审批 |
| CRM、库存、规则、业务审计 | 本项目实现并持久化 |
| 触达调度、渠道幂等、ERP 同步 | 本项目持久任务与适配器实现 |

官方文档将 app-server 定位为产品深度集成接口，支持会话历史、审批、流式事件；协议包含 thread/start、thread/resume、turn/start 和 turn/interrupt。它并不是本项目完整后端。[app-server 文档](https://developers.openai.com/codex/app-server)

## 接入选择

- `codex exec`：适合一次性批任务或早期烟测，不作为多业务员实时接待的主接口。
- Codex TypeScript SDK：适合快速启动与恢复线程的程序流程；SDK 文档将自定义客户端的深度集成指向 app-server。[SDK 文档](https://developers.openai.com/codex/sdk)
- app-server：首选验证对象。worker 管理子进程，通过 stdio 通信，避免直接暴露到公网。程序身份、线程路由、进程限制、失败恢复由适配层负责。
- 直接 fork Codex 源码：目前不建议作为第一步。存在升级、耦合和维护成本；公开协议满足不了需求时再做源码级评估。
- 自建轻量运行时或其他运行时：作为替换路径，复用同一业务工具和协议，不要求完整模拟所有 Codex 内部语义。

官方说明开源的是 harness 和集成表面，模型访问与托管服务单独处理；不能从开源推断模型免费，也不能直接沿用开发人员个人登录作为公司的服务凭据。[Codex 平台说明](https://developers.openai.com/blog/codex-as-a-platform)

本评估只使用官方公开资料，未声称可直接复用当前桌面应用的全部插件、自动审批或内部协作功能。实际商用身份、部署区域、模型可用性、费用与许可证须在选定部署方式后核验。

## 建议集成形态

```text
业务任务 -> 上下文装配 -> AgentRuntime -> Codex app-server
                                  |             |
                             统一运行事件    MCP 业务工具
                                  |             |
                              AgentRun      权限与业务规则
                                  |             |
                               消息草稿 -> 发送网关
```

runtime 输出不直接发给客户。模型可以提出报价或发送建议，但业务后端重新计算并检查。进程的沙箱审批与“采购已确认有货”“主管批准价格”是不同语义，必须分别保存。

客户销售接待、老客户维护、社媒内容、内部业务员助手先实现为同一 runtime 的不同配置和工具权限，不默认引入多个自主 Agent 相互协商。

Codex 默认偏编码场景，应验证业务 SOP 是否能稳定控制工具选择、话术与客户价保密。不要为减少开发量开启任意 shell 权限或将整个数据库连接交给模型。

## 小规模验证与准入

1. 固定 Codex 版本，使用该版本生成或核对协议 schema，验证 MCP 工具兼容性。不依赖实验性 dynamicTools 作为第一版关键路径。
2. 用模拟库存、两个业务员和两个客户，完成询价提取、无货入池、候选匹配和核验待办；模型不接触真实客户或渠道。
3. 模拟人工接管时 Agent 正在运行、核验过期、货源改价、工具超时和进程重启，确认不会越权或重复发送。
4. 按同一批脱敏样例比较 Codex 与轻量 runtime 的字段完整率、工具正确率、风险拦截、延迟和单询单成本。
5. 验证两个业务员的客户隔离、组织隔离及共享知识与库存访问；验证上下文中没有客户不应看到的成本字段。

准入要求：未核验正式报价、过期报价、越权读取、人工接管后发送和重复副作用场景必须全部被业务系统拦截。模型质量阈值、响应目标与成本上限由业务样例和实测制定。验证未通过时保留草稿与人工辅助模式，不用重写 CRM 来更换 runtime。

文档核查日期：2026-10-07。以上是集成方案判断，不是已完成实现或生产能力证明。

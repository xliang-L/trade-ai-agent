# Git 版本管理

本次初始化本地仓库，默认分支 `main`，架构基线标签 `v0.1.0-architecture`。尚未配置远端，未上传 GitHub；远端仓库与可见性需另行指定。

## 日常工作流

从 main 建立短生命周期分支，例如 `feat/inventory-import`、`feat/quote-verification`、`fix/delivery-idempotency`；一条分支聚焦一个可验收问题。完成后检查差异、运行相关验证，通过 PR 合并；保持 main 可复现，不使用长期 V2/V3 分支。

提交使用 `docs:`、`feat:`、`fix:`、`refactor:`、`test:`、`chore:` 前缀。架构重大变更先更新 ADR；一项提交同时包含实现、必要迁移与文档。依赖开始引入后提交 lockfile，固定 runtime 与 Codex 版本。

## 版本与发布

架构基线用预发布标签，应用尚未实现，不将其称作 v1.0。后续使用 SemVer：第一版迭代为 0.x，MVP 达到验收基线后发布 v1.0.0；产品 V2/V3 是业务阶段，不强制等同软件主版本。破坏协议或迁移兼容性时才提升主版本。

每次发布记录功能、迁移、依赖版本、验证证据和回滚方案。数据库迁移是追加的已版本化文件，生产运行过的迁移不能改写；优先兼容新增再切换读取。应用回滚不等于数据库回滚，删除字段和数据前另做备份与专项计划。

## 数据与密钥

Git 保存代码、文档、契约、迁移和脱敏测试样例。客户资料、供应商报价、聊天附件、数据库备份、运行时会话和密钥不入库；`.env.example` 只使用占位符。已泄漏凭据先撤销再清理历史，不能仅删除当前文件。

仓库目前仅文档与契约，无可运行服务，因此暂不配置假 CI。引入实现后添加 lint、类型检查、必要业务测试、迁移验证和关键风险场景评测；远端创建后对 main 配置 PR 检查和禁止强制推送。
